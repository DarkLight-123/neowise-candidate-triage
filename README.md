# Входящие заявки · Neowise

Менеджер вставляет обращение клиента и получает тему и черновик ответа. Перед отправкой он проверяет текст. Если модель не ответила или вернула неподходящий результат, заявка остаётся для ручного разбора.

## Запуск

Нужен Node.js 20 или новее. Устанавливать пакеты и настраивать ключи не требуется.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Для другого порта задайте переменную `PORT`, например в PowerShell:

```powershell
$env:PORT = 3001
node server.mjs
```

## Тесты

Из корня проекта, в отдельном терминале:

```sh
node --test
```

Тесты сами поднимают HTTP-сервер на свободном порту и закрывают его после проверки. Запущенное приложение им не мешает. Проверяются некорректный ввод, все три темы, пять сценариев сбоя имитатора, структура ответа модели, отмена по таймауту и успешный запрос после ошибки.

## Проверка в браузере

1. Введите «Когда доставят заказ?» и нажмите «Разобрать заявку». Справа появятся тема «Доставка» и черновик.
2. Замените текст на «Заявка [error]» и запустите разбор. Вместо черновика появится предложение ответить вручную; старый текст должен исчезнуть.
3. Повторите с `[timeout]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`. Результат тот же, без технических ошибок на странице.
4. Отправьте пробелы. Поле получит фокус, страница попросит добавить текст.
5. Запустите `[timeout]` и сразу измените заявку. Результат предыдущего запроса не должен появиться у нового текста.

Для проверки достаточно учебных данных. Имитатор сохранён без изменений: даже для разных тем он возвращает один и тот же пример ответа.

## Контракт API

`POST /api/triage`, тело запроса — JSON, например `{"text":"Когда доставят заказ?"}`.

| Ситуация | HTTP | Ответ |
| --- | --- | --- |
| Непустая строка и корректный ответ модели | 200 | `{"status":"ready","topic":"delivery","draft":"…"}` |
| Таймаут, ошибка, битый JSON модели, неизвестная тема или пустой черновик | 200 | `{"status":"manual_review","topic":null,"draft":null}` |
| Битый JSON запроса, отсутствующий, пустой или нестроковый `text` | 400 | `{"status":"invalid_input"}` |

Разрешённые темы: `delivery`, `pricing`, `other`. Строка из пробелов считается пустой. У черновика убираются пробелы по краям; дополнительные поля модели не попадают в ответ API.

## Устройство

- `server.mjs` читает запрос, проверяет `text` и выдаёт HTTP-ответ. Фабрика `createAppServer` позволяет запускать тесты на свободном порту.
- `triage.mjs` вызывает модель и проверяет её ответ в `parseModelResult`. Ограничение ожидания — 300 мс: `Promise.race` возвращает результат вовремя, `AbortController` отменяет работу имитатора, таймер очищается в `finally`.
- `index.html` показывает тему, черновик или сообщение для ручного разбора. Новый ввод очищает результат, а счётчик изменений не даёт запоздалому ответу перезаписать новую заявку. Текст модели вставляется через `textContent`.
- `mock-ai.mjs` — исходный имитатор. `test/triage.test.mjs` — тесты на встроенном `node:test`.

Браузер ждёт ответ сервера до 5 секунд, чтобы при сетевом сбое кнопка не оставалась заблокированной. Это отдельное ограничение; ожидание самой модели на сервере составляет 300 мс. Черновик не отправляется клиенту автоматически и не сохраняется между открытиями страницы.

Пользу можно оценить по медианному времени от открытия заявки до готового к отправке ответа и доле черновиков, принятых менеджером без правок.
